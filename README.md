# Ответы на вопросы по CI/CD

**Чем отличается CI от CD?**  
  CI (Continuous Integration) отвечает за автоматическую сборку и проверку кода (тесты, линтеры) при каждом изменении. CD (Continuous Delivery/Deployment) отвечает за автоматическую доставку и публикацию проверенного кода на рабочий сервер (продакшен).

**Что произойдёт, если тесты завершатся ошибкой на этапе CI?**  
  Пайплайн немедленно остановится, дальнейшие шаги (включая развёртывание) выполняться не будут, а разработчик получит уведомление об ошибке. Это защищает сайт от поломок.

**Для чего используется директива needs: ci в задаче развёртывания?**  
  Она указывает, что задача деплоя (`deploy`) должна запускаться строго после успешного завершения задачи проверки (`ci`). Если CI завершится с ошибкой, деплой автоматически отменяется.

**Что такое артефакт и для чего он передаётся между задачами?**  
  Артефакт — это собранный пакет файлов сайта (в нашем случае папка `dist/`), который сохраняется после этапа проверки (`ci`) и передается на этап развёртывания (`deploy`), чтобы на сервер попал ровно тот код, который успешно прошел тесты.

**Почему развёртывание не запускается на Pull Request?**  
  Потому что Pull Request — это лишь предложение изменений (черновик), код еще не слит в основную рабочую ветку (`main`). Публиковать непроверенные или незамердженные изменения в продакшен нельзя.
